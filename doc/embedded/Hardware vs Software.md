# Hardware vs Software

В мире обычного программирования это разделение довольно чёткое: есть "железо" — процессор, память, диски, сетевые карты, — и есть "софт", который на этом железе работает. Они живут в разных мирах, общаются через API и драйверы, и программисты редко задумывается о том, как именно ходят команды и пакеты.

В **embedded** эта граница **размыта до полной неразличимости**. Вы не просто пишете код, который _использует_ железо — **вы чаще всего должны разработать, собрать и отладить железо**, на котором будет работать ваш код!

## HW/SW Co-Design: Совместное проектирование

На практике **embedded-системы рождаются из симбиоза железа и прошивки для него**, когда инженер (или команда) с самого начала рассматривает задачу **целиком**, распределяя реализацию функций между железом и кодом так, чтобы получить максимум производительности, надёжности и энергоэффективности при минимуме затрат.

Решение, принятое на стороне схемотехники, может либо **упростить** программную реализацию в разы, либо сделать её **невозможной**. И наоборот: правильная архитектура ПО может компенсировать отсутствие дорогих аппаратных блоков, но только если вы знаете, _как_ и _где_.
